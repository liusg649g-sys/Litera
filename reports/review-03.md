# 评审记录初稿 · review-03 · 注入类自审

**状态**：初稿，待人工复核并定稿。

## 用什么手段查

- AI 自审 + 脚本反例：SEC-07 静态扫描前端原始 HTML 注入点；`inj01`～`inj03`、`qa-injection` 动态用例。
- 记录：`reports/security-precheck.md`、`reports/security-baseline.md`。

## 查了什么

- SQL 注入：文献搜索的关键字是否直接拼 SQL，注入后是否还能拖出全部数据。
- XSS：文献标题写入 `<script>` 后，列表/详情是否原样转义，前端是否存在 `v-html`、`innerHTML`、`outerHTML`、`document.write`。
- CSRF：伪造 `Origin`、缺少 CSRF token 的写请求是否被拒绝。
- 提示词注入：PDF 内容中的“忽略以上指令”等文本是否被模型当成系统指令。

## 判据

- 注入参数只能返回空结果或正常过滤结果，不得扩大结果集。
- 前端原始 HTML 注入点 0 命中；标题按文本显示，不执行脚本。
- 伪造 `Origin` 的写请求只要非 200 即视为被拒；无 CSRF token 的写请求必须 403。
- 模型回答不得执行文档内指令，引用内容只作数据。

## 结果

- INJ-01：注入查询返回 0 条，没有拖出全部数据。
- INJ-02：注入标题原样保存，列表/详情均转义，SEC-07 扫描 0 命中。
- INJ-03：首次把判据写成“伪造 Origin 必须 403”，实测返回 422（签名与 Origin 域不匹配）；判据改为“非 200 即视为被拒”，并固化为用例常驻。
- QA 提示词注入：回答未执行文档内指令，注入内容只作为引用数据。
- `make check-security` 中 5 条动态反例全部 PASS。

## 未覆盖与人工复核

- 前端单元测试尚未覆盖所有组件，静态扫描只能证明没有明显原始 HTML 注入点。
- CSRF 判据“非 200”比“403”宽，需人工确认 422 是否由签名校验先触发，以及是否仍需统一错误码。
