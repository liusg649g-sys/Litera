# Design

## Context

动机见 proposal.md。Jialu Ma负责，待实现。当前无模型或向量服务；问答上线依赖 05 完整正文/分块和索引就绪，面板由 02 提供，不与布局混合开发。

## Goals / Non-Goals

**Goals:** 检索及回答严格限制当前私有文献，引用可核验且可导航，证据不足明确拒绝下结论。

**Non-Goals:** 不做跨文献全库聊天、科研工作台或自行引入公开外部证据，不实现此阶段业务。

## Decisions

1. 采用 RAG：校验身份/context → 检查提取版本/索引 → 按 ownerId+documentId+版本检索 → 仅发送必要片段给 LLM → 核对引用 → 返回 AnswerDTO。相比直接把全部 PDF 发给模型，更方便证据定位与预算控制。
2. MySQL pages/chunks 为证据真源，向量索引派生可重建；embedding/向量后端使用适配器。05发布最新完整提取后，06仅在新索引就绪时切换rag_indexes活动版本；无活动索引返回503，有旧活动版本则答案明确其版本。模型不得自行决定引用页码。
3. 摘要/结构解析使用覆盖文献各部分的证据聚合，而非仅对一段 top-k 做全文结论；输出每部分引用，缺失部分明确标记。检索不足返回 insufficient_evidence，外部错误走标准包络。
4. PDF 文本作为不可信数据而非系统指令；提示词约束忽略文献里的越权命令，不给模型执行工具/读其他文献的权力。服务端复核引用 chunk、页码和 quote。
5. 02 提供 contextRevision、面板和 citation-navigate；06 提供状态/真实结果。初版完整 JSON 响应，暂不增加 SSE、多轮会话；保存笔记经 04，不直接写其表。

## Risks / Trade-offs

- [幻觉/提示注入] → 证据核验、文献内容隔离、拒绝无依据回答，场景测试。
- [模型延迟与预算] → 受控片段/请求限额、超时、取消，参数后续配置。
- [索引漏删或串用户] → 强制 owner+document+version 过滤，删除作业清理向量，二次校验 chunk。
- [摘要局部偏差] → 全文分段覆盖与引用聚合，不以单次局部检索代表全文。

## Migration Plan

后续增加 qa_answers/rag_indexes 与供应商适配器 → 05 版本建索引 → 权限/证据问答 → 02 面板/引用 → 04 保存联调。回退关闭问答入口，保留页文本及来源，不影响文献管理/阅读；重建索引无需重写原 PDF。
