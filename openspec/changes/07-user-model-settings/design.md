## Context
ModelProfile/ProfileResolver 已支持用户作用域，现有 OpenAICompatible 仅用于受信开发者配置。翻译已有来源签名、取消、限流及旧响应失效机制。
## Goals / Non-Goals
提供实际设置页面和用户模型翻译；不实现QA或多配置管理。本轮交付兼容授权增加Linux文件Vault，保留Windows既有行为。
## Decisions
1. 单用户单配置，以登录用户为主键；不接受ownerId。随机 revision CAS 防止覆盖、删除重建ABA和迟到测试结果。修改即撤销验证；保存无外部请求。
2. DPAPI CurrentUser + 用户ID用途绑定附加熵，数据库只保存受认证密文；不启用LocalMachine，不允许明文回退。跨机器/Windows账号迁移后需重填Key，数据库备份本身不包含DPAPI主密钥。加密适配器可替换，未来Linux必须先配置独立安全密钥服务。
3. 首版只允许HTTPS443、公网IP/DNS，禁止userinfo/query/fragment/反斜线/编码路径/点段及私网、回环、元数据。每次实际TCP连接解析全部IP并拒绝任一非公网地址；连接数值IP，TLS仍用原域名SNI和系统CA。无代理、重定向、自动重试。仅POST固定/chat/completions。
4. 连接测试只测试已保存版本，固定非私人提示、32token、15秒总时限、每用户3次/分钟、全局2并发。错误只返回固定文案和安全代码，不返回上游body。
5. 用户翻译需明确选择user，验证当前所属配置且测试成功；调用失败绝不回退。返回后复核revision；前端配置选择切换使旧请求失效。现有developer默认不变。
6. additive 0008，仅新实例和临时测试应用。旧启动器保持0007 guard，因此现有5180不得直接重启到新head。新预览默认关闭开发者.env读取，无Mock，实际网络仅用户主动测试/翻译。
## Risks / Trade-offs
DPAPI保护依赖Windows服务账号；账号/主机失陷超出数据库密文保护范围。公网HTTPS白名单策略不允许自建内网模型，需后续管理员明确策略设计。httpcore网络后端挂接为受版本测试约束的内部接口。
## Migration Plan
先在临时0007库种合成用户/笔记，SQLite在线备份并SHA256及恢复完整性验证，再升级0008验证原数据不变。新独立实例初始化0007、备份验证、再迁移0008；不在现有5177/5180执行。失败保留现场不覆盖恢复。
## Open Questions
真实网关兼容性与费用由用户在新页面主动测试；本轮自动化只使用受控替身。

## 2026-10-26 GitHub交付兼容性补充
用户授权交付准备，保留已验收界面，不迁移真实密钥。Windows auto继续DPAPI；Linux通过USER_MODEL_SECRET_BACKEND=aesgcm_file与USER_MODEL_MASTER_KEY_FILE启用AES-256-GCM。主密钥为独立权限0600/0400的32字节随机密钥base64文件，放仓库/数据库/构建上下文之外，以只读secret挂载。每次加密随机96bit nonce、owner+用途AAD、128bit tag，密文带格式标识，复用0008已有encryption_scheme，不新增迁移。旧DPAPI密文不自动转换，方案不匹配安全拒绝并要求用户明确重填；禁止替换主密钥后假装旧密文可读。真实密钥转换/轮换须另行授权。
可选compose.user-models.yaml负责secret挂载和显式启用，基础Compose默认关闭个人模型、透传非秘密开关及已有后端开发者配置；不用compose config展开真实值做审查。Docker子目录构建忽略所有.env变体/数据库/备份/缓存。测试密钥仅临时生成，已运行5183不重启、不加载兼容补丁。
