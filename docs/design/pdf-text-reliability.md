# PDF选区文字可靠性与映射异常（2026-10-22）

## 本次根因证据

用户指定tcsec_pdf物理第5页。主要Type1子集字体无ToUnicode，Encoding Differences采用/G01等不携带文字语义的名字；Symbol字体另有映射，不能把所有“没有ToUnicode”的PDF都一概当坏文件。

同版PDF.js getTextContent有183个条目，合并5045字符，其中3381个非制表/换行控制字符，ASCII字母仅19。隔离Chromium中的原生Range选区23字符，与Litera readSelection提取结果逐字一致；不是翻译侧栏额外制造乱码。这里验证的是浏览器默认复制所依赖的原生选区文本，未读取/修改系统剪贴板，也未声称执行过系统Ctrl+C粘贴验收。没有把真实PDF正文写进公开报告/测试源码。

pypdf提示匿名CFF字体编码支持不足；PyMuPDF提取同样异常，没有独立的正确文本可直接回填。字体轮廓可用于正常显示，并不意味着存在正确的Unicode文字。没有安装依赖来猜字体，也没有以显示结果臆造原文。

## 最小处理与兼容性

readSelection保留原字符、textRanges和归一化坐标；可选ReaderContext.textExtractionIssue只携带警告，不进入批注position结构或数据库。PDF.js原始数据/原PDF/绘制未改。新textQuality模块检查不可移植的控制字符、替换符、私用区及孤立代理字符，并按字体聚合检测，避免只选该字体中的可打印碎片时漏放行；每页提取结果用WeakMap缓存，不长期强持有文献实例。

翻译面板遇警告显示明确说明，按钮禁用，工具栏主动请求也被拦截。原始源数据仍在内存，不进行替换、删除、Unicode猜测或自动OCR；批注仍使用原几何逻辑。后端独立验证异常字符及来源页不透明字体编码，返回422 PDF_TEXT_UNRELIABLE，模型不会被调用，不能信任客户端自称可靠。

本次防护是保守检测，不是所有PDF映射的语义正确性证明。正常英文、中文、希腊字母、数学符号、标点、连字和常规换行允许；缺少ToUnicode但标准编码/可靠字形名的正常字体不一概拒绝。后端对存在不透明/Gxx字体的页面采取整页保守拒绝；混合可靠/异常字体页可能因此无法翻译，即使某选区看似正常。没有通过放宽规则或删异常字符掩盖风险。

## 可靠解决办法与人工验收

优先取得作者/出版方提供、带有效文字映射的PDF或可信文字版。只有掌握权威原始映射时才能修补映射，不能把Gxx猜成英文字母。否则在独立副本上OCR并人工逐句校对，特别检查双栏顺序、连字符、公式与专有名词；本轮不安装或调用OCR，不向外部模型发送私有文献。

不要覆盖当前PDF：新OCR副本可能改变文本项/几何，已有批注不能假定自动兼容。未来应在用户授权后作为新文献导入，保留原文与批注。

验收：刷新5177→打开tcsec_pdf第5页→选英文正文→展开“译”应显示“无法可靠提取原文…已阻止翻译”，不显示伪造原文、不发送请求；再用正常可复制PDF验证选词/句/段落、原文与页码正常。本次真实模型未配置，正常PDF仍会在明确点击后显示模型未配置，这与字体错误是不同错误。

自动化覆盖正常Unicode、异常控制/私用字符、字体范围和可打印碎片、后端独立阻断；浏览器使用合成正常/异常PDF及仅本机显式提供的真实第5页。私人PDF不提交仓库，测试模型为Mock或无调用。实际批次和部署状态以统一LITERA_HANDOFF最新记录为准。


## 2026-10-23：行尾断词与原始选区分离

翻译接口在异常字符和字体映射检查通过后，仅对英文尝试有界断词规范化。pdf_text.model_input_text 从同一实际PDF页读取简单正向坐标及行末/下一行首证据；词形限定为经确认的 disorders、therapies、ultrasound。其他词、真正复合词 high-intensity / label-free、同行连字符、复杂/旋转布局、跨栏或大段间距等无法确定的情况保持原样，不声称通用英文纠错。

原始请求text、响应originalText、ReaderContext.selectedText、selectionPosition/textRanges/批注坐标、原PDF字节都不改。只有实际合并时响应额外包含modelInputText与normalizationCount，模型接收单独文本；前端在成功结果下提供“已按 PDF 换行证据合并断词”的可展开说明，仍显示原始选区以供核对。旧客户端可忽略可选响应字段；公共生产者translations.py与消费者translation.ts/TranslationPanel.vue同步，未新增必填入参或迁移。

这是排版断词规范化，不能恢复缺失ToUnicode的乱码，不会删除异常字符或绕过已有前后端保护。自动化采用真实合成PDF/pypdf和PDF.js，以及明确Mock的模型；真实文献的各种版式仍需人工核对，不能以少量词表覆盖所有断词。
