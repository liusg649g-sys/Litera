## 实际代码与数据契约

- `backend/app/models.py:Note/NoteDocument`：独立笔记和多对多关联，笔记无 document_id。`sources=[]`、`source_schema_version=1` 预留后续来源结构，不开放客户端写任意来源。
- `backend/app/notes.py:create_note_router`：本人笔记 CRUD/分页、关联与解除、Origin+CSRF、双端归属校验、客户端 UUID 创建去重、正文 version CAS。完全相同内容的重复提交可返回已保存版本，不放宽对不同内容的冲突检测。
- `frontend/src/notes.ts:createNotesController`：800ms 停止输入后串行自动保存、服务失败不无限重试、409 保留本地输入、按账号/笔记隔离的 sessionStorage 草稿、旧请求失效。
- `frontend/src/components/NotesPanel.vue`：列表/标题正文/新建/关联/解除/删除确认，保存状态和手动重试。普通 input/textarea 转义显示，不执行 HTML；项目暂无已接入的富文本编辑器，本轮不引入新依赖。
- `frontend/src/views/ReaderPage.vue`：独立开关和离开保存守卫。`reader/extensions.css` 只影响共享容器内的扩展侧栏；1700px以上并排，中等宽度右侧上下排列，窄屏底部上下抽屉并在各面板内滚动。收起不销毁编辑状态。
- `TranslationPanel.vue` 仅增加面板开关事件供共享布局使用，不改变翻译业务或模型设置；ReaderContext 字段保持兼容。

关联与正文分离：从文献 A 关联到 B 使用同一 note ID，正文更改两处共享。解除当前关联只删除一行关系；删除笔记明确确认后删除正文及所有关系。文献软删隐藏该入口，恢复后保留关联；永久删除文献仅级联删除关系，笔记仍可从个人已有笔记关联回来。

## 数据库兼容与增量迁移

`0007_literature_notes` 以前一版本 `0006_reader_assets` 为父，只创建 notes/note_documents 和索引，不改旧表、不改 PDF/图片文件。notes 主键 UUID、owner 外键，title 200字符、纯文本 content 上限100000字符、version CAS、来源版本/JSON及创建更新时间；关联表复合主键(note_id,document_id)、owner、创建时间。关联外键 CASCADE 只删除关系。

SQLite 继续使用既有外键开启方式。MySQL 两个新表显式 InnoDB、正文 MEDIUMTEXT、时间 DATETIME(6)、JSON 由应用赋值而不依赖不兼容的默认表达式。前置旧表同样需要支持外键的存储引擎。MySQL 离线 DDL 检查只能证明生成语句，不能证明实际迁移、锁竞争或时间戳问题已通过真实 MySQL。

`GET /api/v1/notes/config` 只读检查必要表/列，绝不创建/修复 schema。缺表时 available=false，其余笔记接口503；5177旧 API没有笔记路由时前端把404显示为“笔记尚未部署，等待数据库升级确认”。这不是完整迁移验收，部署仍须单独核对 Alembic版本、索引和外键。

## 真实5177迁移方案（尚未执行，需用户另行确认）

1. 先只读核对实际路径、PID、端口、空闲空间、当前 Alembic版本、SQLite完整性及账号/文献/批注/资产数量；检查全局导出临时目录及资产清理候选。出现新风险即停。
2. 取得确认后使用已有安全停止方式，确认API/Vite停止且数据库无写入进程。联合备份整个 `.cache/local-site` 到项目外 `Litera-backups` 的唯一时间戳目录，含 SQLite及WAL/SHM（若有）、PDF/图片、会话文件、日志。备份可能包含敏感数据，禁止上传/提交或显示内容。
3. 先估算源目录总大小；目标可用空间至少源大小再加安全余量，C/D都保持至少10GB。复制不覆盖历史备份，比较相对路径/文件数/字节/SHA256；备份库只读 integrity_check、foreign_key_check和各表数量一致，检查每条原PDF/图片引用确实有文件。任何失败不升级。
4. 备份验证成功后才执行仅该SQLite目标的0007增量升级。已有 `local-site.ps1 start` 会自动 upgrade head，**本轮不运行它**；将来启动前须确认当前head仍为已审核0007，避免顺带执行未来迁移。
5. 启动后核对真实库版本/完整性、旧数据数量与所有原PDF/图片哈希，两个健康接口、笔记config及实际CRUD；先用独立验收账号/合成PDF，不修改旧文献。保留备份与证据。

失败处置：首次异常即停止，不反复启动，不自行删新表、清库、alembic stamp或恢复覆盖。SQLite检查事务是否回滚、实际表与版本；MySQL DDL可能部分提交，检查实际状态，不假设事务自动撤销。新迁移 downgrade 主动拒绝删除笔记；可回退应用但保留新增表/笔记。任何恢复备份需重新取得明确授权并先保存失败现场；不自动覆盖当前数据。

现有 MySQL/Docker 数据本轮均不触碰。将来 MySQL 部署应另行选择独立测试库，确认联合逻辑备份+PDF资产快照并验证可恢复，再讨论业务库升级；不复用之前损坏存储环境作无验证写入测试。

启动器复用已有venv/node_modules，无依赖安装；先检查端口/路径/既有测试库版本及完整性，拒绝覆盖残留进程清单。仅首次新测试库迁移到已审核0007，既有测试库只允许已为0007；所有日志带时间戳。5秒监控C/D空间，低于10GB停止自己的子进程且保留数据；停止不删除数据库/文件，不终止其他服务。不要直接运行内部 api/supervise 子命令。

## P3-A-Fix：解除关联/删除显示一致性（2026-10-23）

用户第一轮人工验收已通过多笔记、自动保存、侧栏、多文献关联和刷新重登，解除关联/删除显示异常尚待复验，不能标记整个P3-A最终验收完成。

### 复现与根因

本轮先用隔离Mock/会话存储复现四个失败，再修复：1)解除成功只刷新当前列表，不更新预加载个人笔记的documents；2)删除后个人缓存残留；3)变更前的列表GET晚回可把已移除笔记重新显示；4)保存期间请求切B又回A，旧setDocument(B)可能最后才生效。另有删除/解除成功后重拉列表失败却保留旧条目的路径，以及缺少成功反馈。

真实临时SQLite/API和直接DB检查显示解除A后仅余B、标题正文版本时间不变、重复解除幂等、重登保留；全局删除后笔记和关系均消失。已有预览日志亦有解除200/删除204，但日志无截图前后快照，不能把已复现路径断言为用户截图唯一原因。没有修改后端业务、数据模型或迁移。

### 最小修复

`frontend/src/notes.ts` 的unlink使用响应DTO更新个人关联缓存、立即移除当前列表；remove立即移除当前和个人缓存。两个读取列表和文献切换使用序号/认证及文献上下文检查，变更前旧请求不得覆盖新结果。解除/删除在等待自动保存前记录目标，之后再次核对笔记/文献和busy状态。后续GET失败仍显示操作成功，重试仅GET，不重放DELETE。

`NotesPanel.vue`显示“已从当前文献解除关联。笔记已保留，仍关联：…”或“笔记已删除，全部文献关联已移除。”；个人笔记选择器展示关联标题，明确仅解除关系与全局删除不同。文献上下文未同步时禁用破坏操作，删除二次确认和取消保留。开始新选笔记/新建/关联清除旧成功提示，避免新操作失败仍被旧提示误报为成功；纯读取重试保留已完成操作的事实。
