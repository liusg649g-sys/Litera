# 翻译请求生命周期与性能诊断（2026-10-23）

## 定位与最小修复

旧前端有500ms防抖和迟到响应校验，但显式点击不去重，cancel立即把loading清空；fetch abort不证明后端或模型已停止。隔离实际浏览器/Vite/2秒Mock模型复现：两次取消后，第三次32ms收到429 TRANSLATION_BUSY。原后端slots=2且不排队，没有监听disconnect；本地繁忙拒绝还会消耗20/min计数。历史两个429没有错误码和时长，不能直接归因模型网关。

现在控制器维持真实在途Promise，一次最多一个请求、一个最新候选，500ms稳定后登记；普通新选区使旧结果失效，等待旧调用完成再只译最新选区，避免不断废弃计费请求。关闭、切文献、退出可abort但仍等待Promise结算。后台等待会明确显示“等待上一请求结束，将翻译最新选区”，不是无限队列。同一在途key的显式点击复用Promise，按钮忙时禁用，结果完成后的主动重译保留。

任何429都会清除候选、暂停自动翻译，用户稍后明确点击手动重试才解除；没有自动重试、绕过额度、增加并发或延长原httpx超时。多个浏览器页面各自有控制器，仍由后端每进程总并发2、每用户20/min保护，不宣称跨进程分布式限制。

后端在已消费JSON body后，用一个专用request.receive监听http.disconnect，与模型任务竞争；断开则取消并await任务清理，finally释放槽位；正常成功、异常或外层取消都清理监听任务。它不能保证远端供应商停止计算或退款。后端不新增请求队列；繁忙拒绝不再消耗模型调用计数。隔离复测两次取消后的第三次正常200，两个取消路由约160/154ms结束，第三次约2秒（Mock设定耗时）。

## 计时与错误区分

translation_runtime使用请求级ContextVar，只记录数字、HTTP状态、固定错误码及requestId，不记录原文、文献/用户ID、URL、认证头、密钥或上游错误体。响应增加Server-Timing的translation/pdf/gateway以及X-Translation-Gateway-Status；原响应DTO与来源契约不变。translation是handler范围，不包含进入handler前的认证/依赖；独立探测器另记录整个后端HTTP处理耗时。gateway包括连接、TLS、等待、收包和解析等，不能区分网关内部排队或模型推理。

日志前缀translation_metrics；TRANSLATION_BUSY=本地并发上限，TRANSLATION_RATE_LIMIT=本地每用户频率，MODEL_QUOTA=网关实际402/429。未调用网关时header状态0；取消的内部499不等于用户收到了HTTP499。HTTP 200不能证明文字映射正确，原乱码/所有权/页码检查先于模型调用。

实际少量真实性能采样采用独立8001/5175、临时SQLite、公开合成PDF，模型course-chat每轮只1请求、128输出Token，无重试。前端值为自动化脚本开始点击至译文显示，包含点击自动等待/浏览器调度和网络等；不能当作纯RTT。两个单样本且本机负载可能不同，不能据此宣称模型加速或稳定延迟分布。准确数值及本轮测试结果见统一LITERA_HANDOFF最新记录。

## 来源与工具栏

译文区只用“当前选区译文”或“上一条译文”表示关联；下一行保留标题/物理页/方向，旧结果可展开对应原文。当前判定包含raw、doc、page、direction、positions，后端响应contextRevision与原文严格校验继续保留，历史结果不会覆盖新选区。

工具栏“面板”原来为“译”：toggle，手动只开关；实时展开可能500ms后请求，收起暂停。工具栏“翻译”原来为“译选”：与面板内“翻译/重试”都是同一个request(true)，展开面板并主动发送；忙态均禁用。两个工具栏按钮独立自适应宽度，保留原可访问名称，不在固定32px按钮中塞长文字。

## 验收

刷新5177，选允许外发的正常PDF。手动打开面板不发请求；点翻译后按钮禁用，切新选区时旧结果标上一条且可查原文。实时快速选词：500ms稳定前不调用，模型在途时显示等待，结束后只译最终选区。收起重开保持结果，旧返回不能覆盖新选区。真实网关限流时自动暂停，不要连续点重试。模型Key、PDF原件、数据库结构与用户资料均不为本轮修改。
